# 原理、来源与验证边界

## 1. 数据链

```text
MT / Android shell
  → 检查设备、CPUCP 固件及已加载原厂 SCMI 模块基线
  → 按需加载 live_voltage_scmi_v1.ko
  → 连续两次读取模块的 sample 只读参数
  → SCMI PERF 0x13 的新 GET 请求
  → CPUCP 查询时读取硬件档位配置并计算功耗
  → 返回频率 / 功耗 / 等级索引
  → 整数区间唯一反解 mV，回代检查，计算娱乐分数
```

源码：[`cpu_voltage_probe.c`](../src/kernel/cpu_voltage_probe.c) 的 `report_get()`、`collect()`、`wire_query()`；[`run_core.sh`](../src/mt/run_core.sh)；[`decode_score.awk`](../src/mt/decode_score.awk)。

KO 不使用 Linux `est_power_get()` 旧缓存入口，而是经过现有 SCMI 传输层发出新请求。命令白名单只有 VERSION、ATTRIBUTES、DOMAIN_ATTRIBUTES、DESCRIBE_LEVELS 和 LEVEL_GET；没有 LIMITS_SET、LEVEL_SET，不直接映射或写入 MMIO。

## 2. 为什么能从功耗反解电压

已分析的 CPUCP 镜像 SHA256：

```text
2a2b9ce917e06cd4aafdfc4cd42c9cf63c7e627df46f7682f3769f38121662c5
```

这个特定版本的 PERF 描述路径 `0x1bb0e98a` 调用功耗函数 `0x1bb0d230`，后者调用 `0x1bb0d19e` 读取档位配置。分析到的两个簇基址为 `0x16480000`、`0x164a0000`，配置来自 `+0x3400`，档位行来自 `+0x3000 + 4 × idx`。这里是对原固件读取路径的描述，**不是本模块自行读写这些地址**。

该版本计算关系为：

```text
V_mV = (((config >> 1) & 0x3ff) + (row & 0xff)) × ((config >> 25) & 0xf)
P_uW = floor(V_mV² × C × F_kHz / 1,000,000,000)
C = 100（CPU0–5）或 136（CPU6–7）
```

对返回的 `P`、`F`，求满足下式的全部整数 `V`：

```text
P × 10^9 ≤ V² × C × F < (P + 1) × 10^9
```

仅当整数解唯一、符合范围并能精确回代恢复 `P` 时接受。不能只开平方后四舍五入，也不能把不同固件的功耗系数默认当成相同。

以上寄存器/调用地址来自对匹配固件的反汇编分析，不是厂商公开电压 API。原厂镜像不随仓库分发；独立复核该路径需自行取得**同一哈希**的固件。本仓库可以复核协议采样、反解、拒绝条件和分数，不能仅凭仓库中的文字再次证明固件反汇编结论。

## 3. “正在使用”能说到哪一步

已获得的证据组合：匹配的代码数据流、新 SCMI 响应、唯一反解及同次开机的校准完成日志。此前连续 4 轮、合计 152 个 GET 事务均完整成功，32 档与当时 EM 表一致；当前等级读数也曾随运行改变。

据此，本工具报告的是**查询时 CPUCP 从本机硬件档位寄存器计算并上报的配置**，而不是直接抄写固件默认常量或重复读取旧 EM 缓存。

仍不能证明：

- PMIC 引脚在任意瞬间的真实电压、过渡压降或全部补偿状态；
- 每档相对出厂默认值调整了多少——没有同机校准前基线；
- 这些电压是最低稳定值；
- 分数能够预测超频潜力或物理故障。

同机后续启动/状态下部分档位曾相差 4 mV。变化原因未确认，不能归因于本工具降压；本工具没有写电压。

## 4. 严格接受与拒绝

- 协议版本 `0x40000`、属性、两个域及每域 16 档均需匹配。
- 拒绝缺行、重复行、频率/等级字段不一致、非唯一反解和两次表格变化。
- 第二个样本编号必须递增；输出频率为 MHz，而协议输入为 kHz。
- 实际遇到过“32 档完整，最后 NCC1 当前等级查询返回 -22”。只在严格符合该状态时保留表格，明确显示当前等级不可用。原因未确定，不擅自解释成休眠。
- 新固件或 ABI 不明时，不能靠“数值看起来合理”放行。

## 5. v2 实测状态

完整单文件在本机 Android Shell 实际执行：内嵌文件校验、解包、按需加载、新查询、评分、报告保存及临时目录清理均已完成，显式手机端状态码为 0。v2 该次两轮都有上述可选当前等级 -22 警告，不能把这次写成所有 GET 都成功。

当次分数为 3217 / 1856 / 2536；固定原作者旧样本为 3176 / 1818 / 2497。本仓库的查询夹具来自该次已保存的原始响应，未包含序列号、IMEI、完整设备日志或会话记录。夹具回放只能测试解析器，不能替代硬件实测。

早先一次非交互 ADB 测试停在“按回车退出”，测试侧终止了该等待进程；之后明确设置 `CPU_VOLTAGE_NO_PAUSE=1` 再完整执行，返回 0。MT 界面点击执行尚未验证。

## 6. 兼容设计与恢复

KO ABI 基线包括导入符号 CRC、SCMI 结构偏移、KCFI 调用签名、工具链设置和协议语义。详见 [`profile-v2.json`](../abi/profile-v2.json) 及源码中的断言。

完整 `uname -r` / vermagic 版本号相同不是普遍必要条件；稳定 KMI 范围内有跨版本复用的空间。但稳定 KMI 不保证所有厂商私有布局和固件算法永不变化。v2 是保留旧保护的已验证快照，跨版本需要另立可验证的 ABI 适配，不应以删除 CRC 代替真正去除依赖。

模块没有 hook、定时轮询、自启或卸载入口。停止运行脚本不会移除已加载模块；**正常重启清除，不要强行 rmmod**。
