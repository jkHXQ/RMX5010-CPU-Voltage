# 构建、测试与对应源码

## 不需要编译即可使用

`dist/` 是此前实机验证的 v2 原始发布文件，未因本次开源修改字节；`prebuilt/` 中 KO 与单文件脚本内嵌 KO 一致。`abi/release-v2.json` 保存对应源码及二进制的 SHA256。

## 核验与重打包（不触及手机内核）

需要 Python 3。Linux / Termux 还可用系统 awk 回放解析器：

```sh
python3 tests/verify_release.py
python3 tests/score_regression.py --awk /system/bin/awk  # Android / Termux
# Linux 用：python3 tests/score_regression.py --awk awk
python3 tools/pack_mt.py
```

`pack_mt.py` 只读 `src/mt/` 和 `prebuilt/`，写新 `build/` 文件；不覆盖 `dist/`，固定原始 gzip 时间戳以便重现。Python/zlib 版本不同可能导致压缩字节不同，脚本会明确报出，不能把新哈希冒充旧实测文件。

夹具来自已保存的 v2 新查询响应。其余拒绝样本是测试程序临时生成的合成坏数据，**不是真机再次执行结果**；不会调用 `insmod`、SCMI 或任何频压设置接口。

## 编译 KO

需要：

- 与目标 ABI 匹配且已准备的 ARM64 Android 内核源码/头文件树，包含 generated headers、可运行的 `scripts/mod/modpost` 和 `scripts/module.lds`；
- `include/linux/qcom_scmi_vendor.h` 与 `drivers/firmware/arm_scmi/protocols.h`；
- 原构建使用 Termux Clang 21.1.8 / ld.lld，以及 Python 的 pyelftools；
- 本仓库的 `abi/Module.symvers.v2`（只有这个模块实际用到的 9 个导入项），以及已验证的 ABI profile。

```sh
python3 tools/build_ko.py \
  --kernel "$HOME/projects/kernel-src/ksrc-6.6.89-v" \
  --output "$PWD/build/ko-v2" \
  --clang clang --ld ld.lld
```

输出目录必须是新目录。构建器不会运行 `modules_prepare`，不会改旧内核树，不会加载或卸载 KO。目标 UTS 元数据取自已验证的原厂模块基线，保留 CRC、KCFI、布局断言和原工具链安全选项；不是编译后抹掉 ABI 检查。源码中的 v2 断言和协议限制没有改变。

开源构建器将原构建脚本的硬编码路径改为参数，并将先前从原厂 KO 读取的版本/CRC 元数据保存为 `abi/profile-v2.json`，因此无须把原厂闭源二进制放进仓库。编译/链接命令仍按原流程执行，每条命令、输出和状态码记入新构建目录中的 `build-manifest.json`。

编译依赖的完整 Linux/Android 内核树属于系统构建前提，不在本仓库内；仅凭这份源码不能断言任意源码树、内核版本或工具链构建出的模块都可运行。成功编译或加载也不是电压功能验证。原版本的实机验证范围见 [README](../README.md)，本次发布核验结果见 [`release-validation.json`](../release-validation.json)。

## 对应关系

```text
src/kernel/cpu_voltage_probe.c → prebuilt/live_voltage_scmi_v1.ko
src/mt/* + prebuilt/*.ko       → dist/SM8750_CPU体质测试_MT直接执行_v2.sh
单文件脚本 + 原使用说明        → dist/SM8750_CPU体质测试_MT单文件版_v2.zip
```

当你修改源文件时，应标注修改情况、生成新版本，并在匹配设备上重新测试；不要沿用 v2 的“已实测”标签。GPL 对修改版分发和对应源码的要求见 [LICENSE](../LICENSE)。

## 本次开源发布验证

2026-10-31，在原准备好的 Termux 内核树/工具链上，用本仓库构建器重新编译，KO 的 SHA256 与原实测 KO **完全一致**；在电脑和 Termux 重新打包，单文件脚本 SHA256 也与原实测文件一致。8 项 Android awk 接受/拒绝回放测试通过。本次没有再次加载新 KO，也没有进行频压写入。

准备期间修复了生成 `Module.symvers.v2` 时的 Windows 换行问题，以及传输覆盖较短文件后残留旧尾部的问题；最终以 LF 文件重新写入并核对哈希后通过。没有通过删除 CRC 或 namespace 校验来绕开失败。
